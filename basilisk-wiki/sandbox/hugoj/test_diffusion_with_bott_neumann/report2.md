# Report 2: T_cst GPU drift — attribution and next steps

*Date: 23 September 2026. Follows report1.md (`simple.c` ulp study). All experiments
under `test_diffusion_with_bott_neumann/`, Basilisk sources unmodified except the
sandbox headers listed below.*

## TL;DR

**`vertical_diffusion2()` and `vertical_diffusion_delta()` are both exonerated.**
In isolation (100 calls, constant T, zero flux, CUDA float32 fast-math) both keep
T **bit-exactly at 20.0** (max |T−20| = 0 over all calls). The T_cst GPU drift is
produced by the **vertical remapping (`layered/remap.h`)**, which runs every
timestep and perturbs T by a few −ulp per step, one-signed because of fast-math
divisions. Without remap, the whole coupled run is bit-exact (exactly 0.0 on
CUDA float32 for 10+ steps, and exactly 0 on CPU double for the whole run).

### Phase C — in-situ decomposition (`DIAG_STEPS`: A = start of step,
### B = after vertical diffusion, C = end of step; first 10 steps)

CPU double: delta diffusion is a *no-op* (A≡B always); abs diffusion injects
±1 ulp(20)·2⁻³⁵ noise (A→B ±3.6e-15); other ops inject ±1e-15 (B→C).

CUDA float32 (l0, cumulative, ulp):

| i | abs: A→B→C | delta: A→B→C |
|---|---|---|
| 0 | 0 → 0 → 0 | 0 → 0 → 0 |
| 2 | −1 → 0 → −1 | 0 → 0 → −1 |
| 5 | −2 → −1 → −2 | −8 → −8 → −7 |
| 9 | −10 → −9 → −10 | −19 → −19 → −18 |

- delta: **A≡B at every step** (diffusion preserves T bit-exactly);
  all drift is B→C, i.e. produced *outside* the diffusion.
- abs: A→B moves B *up* by +1 ulp when the field is drifted (interacts with the
  drift), B→C drags it back down. Net effect of the pair is still dominated by
  the non-diffusion operators.

### Culprit isolation (bisection of the coupled run, CUDA float32)

| includes | max\|T−20\| after 10 steps |
|---|---|
| hydro + dr (no nh, no remap) | **0.0 exactly** |
| hydro + dr + nh (no remap) | **0.0 exactly** |
| hydro + dr + nh + remap | −10 ulp @ l0, growing ~ −1 to −2 ulp/step |

Same signature on CPU double: exactly 0 without remap vs ±1e-14 with remap.
**⇒ The drift is entirely produced by `event remap (i++) { vertical_remapping() }`.**

## Root cause analysis (remap.h, read-only inspection)

`vertical_remapping()` (`src/layered/remap.h:66`):

1. every step it rebuilds the layer thicknesses: `h[] = H*beta[l]` with
   `beta[l] = 1./nl` (remap.h:38, 129) — `1/30` is inexact in binary;
2. `zpos`/`znew` interfaces are re-integrated from these rounded h
   (remap.h:120-133);
3. `remap_c()` then reconstructs the tracer on the "new" (numerically unequal)
   grid. For a *uniform grid it should be the identity*, but the reconstruction
   involves several divisions (slopes/limiters) that under `-use_fast_math`
   become `div.approx.ftz.f32` (~2 ulp, one-signed for fixed operands), so the
   identity is broken by a constant-sign error per step.
4. The drift is bottom-concentrated (l0/l1 ≈ −312/−291 ulp @ i=100, interior
   ≈ −10 ulp), pointing at the bottom Neumann ghost row of `remap_c`
   (the `0[*], HUGE[*]` BCs at remap.h:151-154) as the error seed, amplified by
   the tridiagonal reconstruction sweep.

Why delta drifts *more* than abs in the fresh runs: the diffusion itself is
exact, but the remap error is proportional to ulp(|T|) regardless of the
diffusion formulation; abs additionally *partially cancels* the remap error
(+1 ulp up-move per step in A→B, see Phase C) — hence abs nets −48 ulp while
delta leaves the remap error unopposed (−312 ulp). The delta form is not at
fault; it just stops masking the remap drift.

## Recommended next steps (S2+ proposals, not done here)

1. **Make the remap a no-op when nothing moved** (cheapest real fix):
   in the test / in `remap.h`, skip `vertical_remapping()` when
   `max|h[] − H*beta[l]|` is already below tolerance (uniform beta, u=0) —
   or guard the event with a user flag. Removes the T_cst drift entirely,
   no GPU backend change needed.
2. **Fix the sign-bias, not the magnitude** (backend, S2): drop
   `-use_fast_math` at `src/grid/cuda/cuda.c:173` (and `:640`), or at least
   `-prec-div=true` (keep FMA). `div.rn.f32` would turn the remap identity
   error into zero-mean ±1 ulp noise instead of a drift. Validation:
   `T_cst_delta.cuda` max|T−20| should drop from 5.9e-4 to ~±2-3 ulp
   oscillation, matching the CPU-double character.
3. **Make the remap identity exact for uniform grids** (upstream fix): use
   `h_new[l] = h[l]` when `beta` is uniform (h is already exact); or
   reconstruct in delta form (same idea as diffusionH_delta: solve for δT of
   the remap and add to T) so roundings scale with ulp(|δT|)=0 instead of
   ulp(|T|).
4. Optional hardening (from earlier review, still valid): split
   `s[0,0,l] = sold[l] + (a[l] = ...)` in `diffusionH_delta.h:88` into two
   statements; initialize `c[nl-1]`; fix the `nl==1` path (reads
   uninitialized `b[0]` combination); fill `sold` via a plain `for` loop.
